# ESM GO Embedding Explorer

The matrix/projection data in `data/` are generated by
`../esm_go_embedding_analysis.ipynb`. The prediction-probe summaries are
generated by `../esm_function_prediction_probes.ipynb`. The PFP metric section
is generated by `../esm_probe_pfp_metrics.ipynb`. The annotated-versus-
unannotated cosine distributions and joint 3D projections are generated by
`../../scripts/build_annotation_latent_analysis.py`.
The Clean PLM test-versus-donor neighbour geometry view is generated by
`../../scripts/build_plm_neighbor_embedding_view.py`.
The post-blacklist KNN-versus-competitor diagnostics are generated by
`../../scripts/build_knn_competitor_analysis.py` and embedded into
`../competitors_performance.ipynb` by
`../../scripts/update_knn_analysis_notebook.py`.
The complete all-method protein–GO score matrices are generated from the
per-method prediction details by `../../scripts/build_pfp_score_comparison.py`.
The general pairwise method-comparison artifact, research report, and CSV
exports are derived from those two existing result sets by
`../../scripts/build_method_comparison_analysis.py`; it does not rerun a model.

Create an isolated analysis environment from the repository root when needed:

```bash
python3.11 -m venv .venv-analysis
source .venv-analysis/bin/activate
python -m pip install -r requirements-analysis.txt
```

Rebuild the KNN diagnostics, report, CSV exports, and notebook section:

```bash
python scripts/build_knn_competitor_analysis.py --project-root .
python scripts/update_knn_analysis_notebook.py --project-root .
python -m unittest tests.test_knn_competitor_analysis -v
```

From this directory, start a local server:

```bash
python -m http.server 8000
```

Then open `http://localhost:8000/`. To open the new analysis directly, use
`http://localhost:8000/?page=pfp&pfp=diagnostics`. The all-model score matrix is
available at `http://localhost:8000/?page=pfp&pfp=comparison`.

The interface provides six organism/domain datasets, cosine-similarity and
Euclidean-distance heatmaps, 2D GO-group UMAP and t-SNE projections, and an
`Annotation status` page. That page compares annotated/annotated,
unannotated/unannotated, and annotated/unannotated cosine distributions and
shows jointly fitted interactive 3D PCA, UMAP, and t-SNE projections with
status, GO-group, and search filters. It also includes kNN annotation transfer,
linear-probe confusion matrices, S2F selected-term comparison where local S2F
predictions are available, full benchmark PFP metrics for ATGO, TALE, PANDA2,
S2F, and clean PLM KNN/Gaussian-KDE transfer baselines, bar-click result details,
UniProt search, stable GO-term colors, tooltips, and metric-specific validation
statistics.

The PFP page includes a `Method comparison` view for organisms `83333` and
`1111708`. It can compare any pair of S2F, TALE, ATGO, PANDA2, Gaussian KDE,
and KNN K = 3, 5, 7, or 10. Organism, evaluation scope, ontology, and
truth-status controls drive a linked set of precision–recall and F1 curves,
global metrics, score distributions and coverage, a paired-score scatter,
threshold-verified disagreement cases, and a concise generated conclusion.
Pair-level panels convert an absent method output to zero and apply the same
conditional four-decimal rounding as the benchmark reconstruction; global
threshold curves use the saved benchmark diagnostics. The view consumes only
current post-blacklist prediction details;
historical pre-blacklist comparisons are not registered in `data/index.json`.
Taxon `223283` is intentionally excluded from every active frontend benchmark
selector and neighborhood filter because only three proteins remain after the
shared evaluation-set filter. Its underlying experiment artifacts are retained
for provenance but are not part of the displayed analysis.

The Method comparison view shows one recalculated Smin for every method. It
uses experimental GO annotations from the full organism to calculate GO-term
information content before the shared evaluation-protein filter, then applies
that same information-content vector to every method's shared prediction
matrix. The generated artifact records the GOA and ontology sources,
annotation counts, and validation difference against the historical
advanced-method Smin values. See
[`doc/knn_vs_advanced_metrics_analysis.md`](../../doc/knn_vs_advanced_metrics_analysis.md)
for the paired-bootstrap details, and
[`doc/method_comparison_research_questions.md`](../../doc/method_comparison_research_questions.md)
for the evidence-based answers across all active methods.

For the annotation-status comparison, `annotated` means at least one direct,
non-`NOT` GO row with a configured experimental evidence code across MF, BP,
or CC in the local filtered GOA snapshot. `Unannotated` means no accepted row
under that definition; it does not claim absence from all-evidence or future
GOA releases. Each existing 60-protein annotated dataset is paired with 60
unannotated proteins selected without replacement by nearest sequence length.
All embeddings are L2-normalized and each projection is fitted jointly on the
balanced 120-protein sample.

The full benchmark PFP rows are generated from the shared competitor/S2F
evaluation protein set. Clean PLM rows use ESM-1b embeddings from `plm.py`,
exclude the complete shared evaluation set and the close-taxon blacklist for
the particular test organism from the Swiss-Prot source pool **before**
neighbour selection,
and transfer propagated GO terms using KNN or a source-calibrated Gaussian KDE.
The active KDE uses one bandwidth shared across the benchmark organisms. For
each target protein it evaluates Gaussian kernels centred on eligible
Swiss-Prot donors, assigns continuous distance weights, and retains every donor
whose relative weight exceeds the numerical floor. The floor is not a fixed-K
rule; more than three donors can contribute. The bandwidth is selected by
macro-averaged source-only pseudo-query performance, without benchmark GO
labels. The previous third/fifth-neighbor adaptive KDE is retained only as a
legacy audit artifact. See
[`doc/clean_plm_kde_radius.md`](../../doc/clean_plm_kde_radius.md) for the
derivation, formulas, command, and generated audit files. The `Result details by
method` tab lazy-loads per-method prediction tables with protein IDs, GO terms,
prediction scores, ground-truth labels, and threshold outcomes. The separate
`Score comparison` tab shows the complete shared protein × GO-term evaluation
matrix for all active methods. Missing model predictions are represented as
`null` in the generated JSON and displayed as `-`; a genuine predicted score of
zero remains numeric. The active KDE column is the shared-bandwidth Gaussian
kernel-support method.

The `Neighbour geometry` page provides interactive joint 3D PCA, UMAP, and
t-SNE views for the Clean PLM shared test set and the Swiss-Prot donors used to
inspect it. The current export keeps every benchmark test protein and every
donor selected by a displayed KNN, fixed-radius, or Gaussian-KDE neighbourhood.
The PCA coordinates are fitted directly from the joint normalized ESM-1b
embeddings; UMAP and t-SNE use a joint 50-component PCA pre-reduction for
memory-safe fitting. Selecting a test protein overlays the exact donor IDs
selected in the original 1,280-dimensional cosine space. The bottom-page GOA
footer exposes the active local filtered-GOA snapshot provenance. See
[`doc/plm_neighbor_embedding_view.md`](../../doc/plm_neighbor_embedding_view.md)
for the cohort boundary and regeneration details.
